# RAG for HiMed MCQ Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Measure whether top-5 passages retrieved (BGE-M3, cross-lingual) from English MedRAG Textbooks + StatPearls raise HiMed-8B's accuracy on the 489 frozen MILU Hindi medical MCQs, against the C0 baseline and a random-passage control.

**Architecture:** A new subpackage `performance_eval/rag/` builds the combined corpus, embeds it into a FAISS exact index, and writes per-item passages to JSONL files (one for `rag_k5`, one for `rag_rand_k5`). The existing generation harness (`run.py` + `prompts.py`) gains a `--passages-file` flag that puts those passages in front of the C0 prompt. A dedicated report module scores the three conditions and runs the two pre-registered McNemar tests. A later, separate step tags question types blind to results.

**Tech Stack:** Python, `datasets`, `sentence-transformers` (BGE-M3 dense), `faiss-cpu`, existing `transformers`/`torch` HiMed wrapper, `literacy_eval.analysis.stats` (McNemar, Wilson), `pytest`, SLURM on PACE.

**Spec:** `performance_eval/docs/2026-11-16-rag-design.md`

## Global Constraints

- Model: HiMed-8B only. Decoding identical to C0: greedy, `{"do_sample": False, "temperature": None, "top_p": None, "repetition_penalty": 1.0}`, model-default `max_new_tokens`, `--seed 42 --gen-seed 42`, scored in `first_letter` mode.
- Corpus: `MedRAG/textbooks` (HF) + StatPearls built locally from NCBI with MedRAG's `src/data/statpearls.py`. Embed field `contents`; prompt shows `title` + `content`.
- Retriever: `BAAI/bge-m3` dense, normalized embeddings, `max_seq_length=512`; FAISS `IndexFlatIP` (exact).
- k = 5, pre-registered, never tuned. Random control seed = 42.
- Retrieval query = question + all option texts. Never `answer_letter` or anything derived from it.
- Bonferroni family m = 2: `rag_k5` vs `c0_baseline`, `rag_k5` vs `rag_rand_k5`. `rag_rand_k5` vs `c0_baseline` is descriptive (no test). α = 0.05.
- Everything large (corpus, StatPearls text, embeddings, index, passages, raw CSVs) lives under `/home/hice1/gchiu6/scratch`. StatPearls text is never committed.
- `literacy_eval/`, model-wrapper defaults, and the C1–C4 ladder outputs (`results_himed.md`) stay untouched. Existing run sidecars (C0, in-progress C1–C4) must still resume.
- No paid APIs. Commits use email grchiu6@gmail.com.
- Work on a new branch `perf/rag` cut from `perf/mcq-techniques`; stage only the files each task names (the working tree has unrelated uncommitted changes).

## Review Focus

- **Passages file doesn't match the test items** (missing an item, extra ids, wrong k): `run.py` must refuse before generating anything, not silently run some items without passages. (Task 5)
- **Resuming an old non-RAG run** (C0, or an approach-1 condition mid-run) after `run.py` gains RAG config keys: must still resume, because the new keys are `None` when RAG is off. (Task 5)
- **Resuming a RAG run after the passages file changed** (re-retrieval, rebuilt index): must be refused via the passages file's sha256 in the sidecar. (Task 5)
- **StatPearls not built or empty** on the cluster: the corpus build must fail loudly, not quietly produce a textbooks-only corpus. (Task 1)
- **Passage ids colliding across the two sources**: ids are prefixed with the source so a collision can't merge two passages. (Task 1)
